# Vision

## The product

An operating layer where a company can discover, install, test and run AI capabilities without assembling an automation stack. The user speaks in business terms. The platform turns the request into a bounded mission with knowledge, instructions, tools, evaluations and approvals.

The long-term destination is a one-human company runtime: humans set direction, policies and exceptions; specialized agents execute repeatable work; the system remembers what was learned and becomes easier to operate over time.

## The core loop

```text
Company context → recommended opportunities → chosen capability
→ knowledge and policy setup → test on evidence → human correction
→ supervised activation → measured runs → improved capability
```

The first experience must work through three equivalent entrances:

1. **Recommendations:** the platform identifies likely high-value work from the website and explanation.
2. **Marketplace:** the user browses capabilities by outcome, role, tool or industry.
3. **Free-form request:** the user writes what they want; the resolver finds an existing capability, proposes a bounded composition, or explains what is missing.

## Five-minute promise

Target: an eligible user sees a useful, evidence-backed first result within five minutes. Eligibility and blockers must be visible. This is measured from account start, not hidden after a successful connection.

The first result can be a market brief, customer-request analysis, meeting brief or sourced content draft. It does not need to execute an external action. Value means that the user would keep or use the result after inspection.

## Principles

- Begin with a business outcome, not a graph editor.
- Treat facts, hypotheses, instructions and third-party content as different things.
- Make every important result inspectable through sources, checks and unknowns.
- Keep test mode free of external side effects.
- Scope autonomy per action and policy, not as a single agent score.
- Make the second capability faster because the first one established company context.
- Let experts bring models, keys and custom tools while keeping beginner UX simple.
- Reuse mature infrastructure; invest deeply in the adaptation and evaluation layer.

## Moat hypothesis

The defensible asset is not the base model. It is the accumulated system that learns how to install reliable work in different companies: capability contracts, company context, protocol variants, evaluation datasets, failure patterns, permission policies and cross-capability objects.

This becomes a moat only if it produces measurable improvement: lower setup time, fewer corrections, better first-pass quality, lower cost per accepted result and faster installation of the next capability.
