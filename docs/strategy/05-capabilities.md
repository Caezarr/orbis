# Capability marketplace

## Capability contract

Every package declares: slug and version, outcome, inputs, outputs, required knowledge, tools, scopes, protocol, evaluation suite, cost bounds, risks, approval points, failure modes, owner and deprecation policy.

## Initial packages

| Package | First useful result | Verification |
|---|---|---|
| Research brief | Sourced and prioritized findings | Source date, relevance, duplicates, claims |
| Meeting preparation | Brief, questions and unknowns | Identity, citations, no unsupported facts |
| Content draft | Draft plus channel variants | Source coverage, instructions, format |
| Request analysis | Structured need and prepared response | Required fields, unknowns, no invented prices |
| Quote preparation | Draft quote with assumptions | Deterministic calculations, catalog version, human approval |
| Tender analysis | Eligibility, deadlines and missing documents | Requirement coverage, citations, risk flags |
| Lead operations | Enrichment, scoring and follow-up draft | Dedupe, consent policy, CRM source of truth |

The first four are safe to test across industries. Later packages add external writes only after the action broker and approval model have been proven.

## Free-form resolver

Parse objective, input, output, cadence, tools and external effects. Match an existing package; compose only approved primitives such as research, extract, compare, calculate, draft, verify and request approval. Show the plan before testing. If unsupported, offer a real intermediate result and record the unmet need.

## Package publication

Versioned manifest, signed artifact, least-privilege scopes, success and failure cases, evaluation dataset, budget limits, owner and rollback. Third-party packages need sandbox execution, dependency scan, review, reputation and removal procedure before publication.
